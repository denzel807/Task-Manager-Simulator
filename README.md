Основные задачи программы:

•  дать пользователю возможность создавать набор процессов с различным временем выполнения;

•  задать квант времени для алгоритма Round-Robin;

•  пошагово визуализировать работу диспетчера (выбор процесса, изменение оставшегося времени и завершение);

•  продемонстрировать логику переключения между процессами и обработки очереди.

  Программа может использоваться в учебных целях, как наглядное сопровождение лекций по операционным системам, а также для самостоятельной работы студентов.

  Вся программа реализована в одном файле Program.cs и включает: класс Process, класс главной формы MainForm и статический класс Program с точкой входа Main(). Такое построение упрощает анализ кода и соответствует требованиям задания (один исходный файл).

5.2 Класс Process
Класс Process описывает модель процесса в контексте планирования и содержит поля:
• Name — имя процесса;
• BurstTime — полное время выполнения;
• RemainingTime — оставшееся время выполнения.
Объекты этого класса используются для хранения набора процессов и их отображения в таблице через BindingList<Process>.

5.3 Главная форма MainForm
Класс MainForm наследуется от Form и включает элементы интерфейса (таблица процессов, поля ввода, кнопки, журнал, таймер), а также структуры данных и переменные, необходимые для моделирования:
• BindingList<Process> processes — список процессов;
• Queue<Process> readyQueue — очередь готовых процессов;
• Process currentProcess — текущий выполняющийся процесс;
• int currentTime — «системное» время;
• int quantum — квант времени;
• int timeInCurrentSlice — сколько тиков уже получил текущий процесс.
В обработчиках кнопок реализованы добавление процессов, запуск/пауза моделирования и сброс состояния.

5.4 Логика работы таймера и диспетчера
Основная логика алгоритма Round-Robin реализована в обработчике события Timer_Tick. На каждом тике проверяется необходимость переключения процесса (конец кванта, завершение процесса или отсутствие текущего процесса), при необходимости текущий процесс возвращается в конец очереди, выбирается новый процесс и выполняется один такт его работы, уменьшается RemainingTime и увеличивается текущее время.

При завершении процесса (RemainingTime <= 0) он не возвращается в очередь, а в журнал выводится соответствующее сообщение. Когда очередь готовых процессов опустеет, таймер останавливается и в журнал выводится сообщение о завершении моделирования.
